# 计算机系统概论（一）：课程引言

> 本系列依据清华大学《计算机系统概论》（张悠慧老师）2026 秋季学期课件整理，参考教材为《深入理解计算机系统（第三版）》（CSAPP）。一讲一篇，第一篇是引言，先把这门课的坐标系搭起来。

## 1. 这门课站在哪里

计算机系统概论是大二秋季学期的系统课组入门课。它前面是 C/C++ 程序设计，后面是计算机组成原理、操作系统、编译原理、体系结构这几门课，相当于把这几门课各取一角，先让你对整台机器有一个完整的轮廓。

它的视角很明确：**从程序员的视角看计算机**。组成原理和体系结构是从"造机器的人"出发，自底向上讲；这门课则把 C 语言程序当作起点，自顶向下追问：一段 C 代码在硬件上到底是什么样子，它是怎样被运行起来的。

![](/obsidian-assets/2fafd06b7d5981a0.png)

上图是课件给出的计算机系统分层：应用软件、高级语言、编译软件、汇编语言、ISA（处理器软硬件的分界线）、硬件描述语言、数字电路。学过 C/C++ 的人，已经站在"高级编程语言"这一层。这门课要做的，是让你能顺着往下看穿几层。

## 2. AI 都能写代码了，为什么还要学

课件里用了一个很小的例子来回答这个问题。三个结构体：

```c
struct A { char c1; int i; char c2; };
struct B { char c1; char c2; int i; };
struct C { char c1; char c2; int i; } __attribute__((packed));
```

典型输出是 `sizeof(A)=12`，`sizeof(B)=8`，`sizeof(C)=6`。字段完全一样，只因为顺序和对齐方式不同，大小就差了一倍。

![](/obsidian-assets/8856c5de3a146cd5.png)

原因是**数据对齐**：编译器要求 `int` 放在 4 的倍数偏移处，不够就在前面补空洞（pad）；整个结构体的总大小还要补齐到最大成员对齐值的倍数。所以 A 里 `c1` 后面补 3 字节，末尾 `c2` 后面又补 3 字节，一共 12；B 把两个 `char` 挨着放，只在中间补 2 字节，一共 8；C 用 `packed` 取消了对齐，6 字节，代价是 `int` 落在偏移 2 的位置，访问可能变慢。

问 AI，它能把这些现象讲清楚。但课件指出了另一件事：面对一个遗留代码库，需要压缩内存占用时，AI 不会自己去扫描所有结构体、重新排字段顺序。你得先明白"为什么顺序重要"，再去权衡空间和访问局部性，这是**优化决策**，不是**现象解释**。

同样的逻辑放大到工程里：应用代码通常被认为与处理器架构无关，但从 x86 迁移到 ARM 时，并不是重新编译就完事。内存一致性模型、向量指令、原子操作与无锁编程，这些地方出的问题往往是"编译能过，运行出错"，需要你对底层有整体判断。

课件把结论归结为两点：

- AI 擅长**单层解释**；而代码设计中的**跨层权衡**和**问题情境的判断**，仍然需要人来做。
- 大模型降低了"写出能跑的代码"的门槛，同时抬高了"写出高效、健壮、可靠、安全、可扩展的系统"所需要的系统思维的门槛。当你面对 AI 生成的代码时，要能穿透它所在的抽象层，去分析底层的约束与代价。

课件中有一张对照表，大意是：系统变慢时，不懂系统的人只会换个问法再问 AI，拿到一堆建议碰运气；懂系统的人会先建立基准、量化瓶颈、逆向诊断根因，再规划迭代路径。这门课要培养的就是后一种能力。

## 3. “体系结构”到底指什么

课件对 Computer Architecture 区分了狭义和广义两种含义，这在后面读书时经常混淆，值得先说清楚。

**狭义**：1964 年 G. M. Amdahl 推出 IBM 360 系列机时，首次引入这个概念，指的是**系统程序员（写汇编、机器语言、编译器、操作系统的人）所看到的计算机系统的属性**，包括概念性结构和功能特性，也就是"为了写出能在这台机器上正确、高效运行的程序，必须了解的东西"。通俗地说，就是 **ISA（指令集体系结构）**。

课件列出的功能特性包括：数据表示、寻址技术、寄存器定义、指令系统、存储系统、异常处理系统、输入输出系统、机器工作状态（如内核态与用户态）。本课程涉及的计算机系统，主要就是中央处理器和内存。

**广义**则分三层：

| 层次 | 英文 | 回答的问题 |
|---|---|---|
| 计算机体系结构（狭义） | Computer Architecture | 程序员看到的计算机系统属性 |
| 计算机组成 | Computer Organization | 这些属性在逻辑上如何实现 |
| 计算机实现 | Computer Implementation | 在物理上如何实现 |

举个对应：同一套 x86 指令集（体系结构），可以有不同的流水线与缓存设计（组成），再落到不同的工艺和芯片上（实现）。这门课主要关心第一层，也就是 ISA 暴露给软件的那部分。

### 冯·诺依曼结构的指令周期

概念性结构上，课件采用的是冯·诺依曼结构：处理器（包含 ALU 与寄存器）、控制单元（含指令寄存器和程序计数器）、存放**指令与数据**的存储器，外加外存与输入输出。它的执行特征可以概括为两点：**以指令为中心**，以及**存算分离**。

![](/obsidian-assets/9aaa15d9ef3cbf26.png)

一条指令的执行循环如下：

1. 处理器根据 **PC（程序计数器）** 的值，从内存中取出下一条要执行的指令；
2. 根据指令的语义执行相应的操作，可能读写寄存器，也可能读写内存中的数据；
3. 根据执行结果修改 PC，指向下一条指令（顺序执行就是加上本条指令长度，跳转则改成目标地址）。

这里有两个后面反复用到的概念：

- **PC**：记录下一条要执行指令的地址。
- **程序状态**：处理器内部的状态，例如寄存器堆、PC 等，它与内存里的程序数据是两回事。

代码在内存里是二进制的机器指令，机器指令的助记符就是**汇编指令**。这一点后面讲汇编时会直接用到：汇编不是另一种东西，它只是机器指令的文字写法。

## 4. 从 `.c` 到运行：编译、链接、执行

"程序"在课件里的定义很朴素：一组告诉计算机要做什么的指令。同一件事可以用 C/C++、Fortran、Rust 来写，也可以直接写机器语言。把高级语言变成机器能执行的东西，要经过两个关键步骤。

**编译**：把用一种编程语言写成的程序翻译成另一种语言。对 C 来说，`.c` 文件被翻译成汇编程序（`.s`），再被汇编成目标文件（`.o`）。目标文件里已经是机器指令，但数据部分、以及对外部符号的引用还没有最终确定。

**链接**：把一个或多个目标文件合并成一个可执行文件（或库文件）。多个 `.c` 文件各自编译成 `.o`，再链接成一个 `a.out`。

![](/obsidian-assets/36efc7bddf1f3bad.png)

这张图把全过程串在一起：左边是 C 源码，经编译得到汇编（`.s`、`.o`），经链接得到带地址的可执行代码，最后运行时，代码和数据被装入内存，CPU 里的 PC 指向第一条指令，开始按上一节讲的指令周期运转。

用命令行看，各阶段的产物大致是这样的：

```bash
gcc -S main.c        # 生成 main.s ：汇编程序
gcc -c main.c        # 生成 main.o ：目标文件（机器指令）
gcc main.c -o a.out  # 链接成可执行文件
objdump -d main.o    # 反汇编，查看机器指令与汇编的对应
```

> 以上命令只用来对应课件中的 `.c → .s → .o → a.out`，课程实验里会大量使用 `objdump` 和 `gdb`。

## 5. 整门课的主线：一个进程从诞生到消亡

课件把整门课组织成一个进程（程序）的生命周期，这是理解课程结构最重要的一张图：

![](/obsidian-assets/e04250c633e9c0f4.png)

左半部分是**C 程序在硬件层面的表示**，此时程序"独占"整个处理器和全部内存：

- **编译阶段**：数据的机器表示（整数、浮点数、数组、结构）；汇编基本指令；程序的机器表示（控制流、函数调用）。
- **链接阶段**：程序链接、内存布局、栈溢出攻击。

右半部分是**程序在硬件层面的运行**，此时要回答"在多任务并发下，那个'独占'的假象是怎么形成的"：

- **启动**：创建虚存空间，`_start` 开始运行；
- **运行**：虚存与虚存管理、异常与异常控制流、动态内存分配；
- **退出**：进程管理，子进程 `exit`，父进程回收。

此外还涉及信号处理、文件 IO、线程与并发。

课件特别强调了一个问题：单个程序看上去独占整个处理器和内存，真实情况却是多任务同时运行，这是怎么做到的？答案是两个核心概念：

- **虚存**：在有限的物理内存前提下，给每个进程一块连续的、相互独立的虚拟内存；
- **异常**：任务切换的重要机制（异常当然还有很多别的作用）。

并且课件顺势提出四个贯穿全课的"跨层次问题"：谁提供了这个假象（编译器、操作系统、处理器三层协作）？用什么机制掩盖（虚存做地址空间隔离，异常做上下文切换）？掩盖的代价是什么（TLB miss、缺页、上下文切换开销）？这个假象什么时候会破裂（比如内存抖动 thrashing）？

## 6. 两条贯穿全课的设计思想

**分层抽象。** 计算机系统自上而下逐层隐藏细节：应用软件、高级语言、编译、汇编、ISA、硬件描述、电路。每一层只对上一层暴露一个接口，ISA 是软硬件的分界线。分层让复杂系统可以分工设计，但也意味着性能问题和正确性问题常常发生在层与层的缝隙里，就像开头的结构体对齐。

**设计思想“朴素”，但实现不简单。** 课件举了三个例子，都是从需求出发的"第一性原理"式解法：

- **基于栈的函数调用**：函数调用要保存现场、层层嵌套，那就造一个后进先出的栈，调用即 push，返回即 pop，一个栈指针就解决问题；
- **异常处理**：正常流程被打断后要保存现场并能恢复，那就让硬件自动保存现场，再通过异常处理向量表精确转到软件入口；
- **虚拟内存**：内存不够用，那就"假装足够大"，缺了再从硬盘搬，用页表加缺页异常把"无限"与"有限"接起来。

课件也提醒：思想朴素不等于实现简单，先掌握核心思想，细节在后续各讲展开。

## 7. 教材、考核与实验

- **教材**：《深入理解计算机系统（第三版）》。要求的章节大致是：第 2 章（2.1–2.4，乘除运算不要求但 2 的整数次幂除法要掌握）、第 3 章（3.2–3.10）、第 7 章（链接，基本全部）、第 8 章（8.1–8.6）、第 9 章（虚拟内存，多级页表不要求）、第 10 章（系统级 IO）、第 12 章（并发编程的部分小节）。
- **计分**：实验约 30%，作业约 10%，考试约 60%。
- **实验**（初步安排三个）：炸弹实验或栈溢出攻击（程序的机器表示与调试）、动态内存分配（空间与时间效率的取舍）、多核调度器（并发加任务状态）。

课件最后还提到一点背景：大模型对算力需求在五年内增长了约 1000 倍，而体系结构与系统层面的优化（Hennessy 与 Patterson 在 2019 年的文章里举的例子是，一个程序经过充分优化后，在多核 Intel 处理器上比最初的 Python 版本快 62000 倍以上）是满足这种需求的关键。这也是"系统能力在 AI 时代更重要"的另一条证据。

## 小结

这一讲要带走的是三件事：

1. 这门课的视角是**程序员自顶向下看机器**，目标是培养跨抽象层的系统思维，而不是再教一遍写代码。
2. 机器层面的基本模型是**冯·诺依曼结构**：指令与数据在内存里都是二进制，CPU 靠 PC 反复"取指、执行、更新 PC"。
3. 整门课沿着**一个进程的一生**展开：编译、链接、启动、运行、退出；前半段讲程序怎样被表示，后半段讲"独占机器"的假象怎样被造出来。
