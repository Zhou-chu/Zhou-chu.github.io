# 计算机系统概论（二）：整数

> 本篇对应课件第二讲《整数》。这一讲的主线只有一句话：**机器里存的只是一串比特，数值是"怎么解读"这串比特的结果。** 理解了这一点，补码、类型转换陷阱、溢出、移位除法都是顺理成章的推论。

## 1. 预备：容量、字长与内存组织

容量单位按 2 的幂计：$1\text{K}=2^{10}$，$1\text{M}=2^{20}$，$1\text{G}=2^{30}$，$1\text{T}=2^{40}$，$1\text{P}=2^{50}$，$1\text{E}=2^{60}$。一个二进制位是 1 bit，8 bit 是 1 Byte（字节）。课件还提醒：Word（字）在 x86 的习惯里是 2 字节（16 位），而 RISC-V 里一个 word 是 32 位，所以"字"这个词要看上下文。

**机器字长**指计算机一次整数运算所能处理的二进制位数，通常也等于地址的长度。它决定了地址空间的大小：

- 32 位字长：地址空间 4 GB，对内存需求大的应用已经偏小；
- 64 位字长：理论上约 $1.8\times10^{19}$ 字节；目前 x86-64 实际只支持 48 位地址，也就是 256 TB。

内存是**按字节编址**的：每个字节有一个自己的地址。一个机器字占若干个相邻字节，它的地址是其中第一个字节的地址，相邻两个机器字的地址相差 4（32 位字）或 8（64 位字）。

## 2. 字节序：一个字内的字节怎么排

一个 4 字节的 `int` 占 4 个地址，那么最高位的字节放在哪个地址？两种约定：

- **大端（Big Endian）**：最高有效字节（MSB）放在低地址，读起来和人写数字的顺序一致。Sun、PowerPC、Java、**网络字节序**都是大端。
- **小端（Little Endian）**：最低有效字节（LSB）放在低地址。x86、RISC-V、ARM（默认）都是小端。

以 `int x = 0x01234567`、起始地址 `0x100` 为例：

![](/obsidian-assets/a911bfed31fd2e3e.png)

再看几个具体数值。`int A = 12345` 的十六进制是 `0x3039`，补码形式的 `-12345` 是 `0xFFFFCFC7`：

| 数值 | 小端（x86）自低地址起 | 大端（Sparc）自低地址起 |
|---|---|---|
| `12345`（`0x00003039`） | `39 30 00 00` | `00 00 30 39` |
| `-12345`（`0xFFFFCFC7`） | `C7 CF FF FF` | `FF FF CF C7` |

**字节序只影响"多个字节如何解读"，所以在两种场合会出问题**：跨机器的网络传输，以及用 `unsigned char *` 去查看内存。课件给了网络传输的例子：发送端是小端，本地值 `0x12345678` 在内存里是 `78 56 34 12`；发送前必须用 `htonl` 转成大端的字节流 `12 34 56 78`，接收端再用 `ntohl` 转回本地格式。如果接收方是小端又没有转换，直接 `memcpy`，读到的就是 `0x78563412`，数值被颠倒。课件让我们顺便想一想：通过磁盘拷贝文件传递数据是否也有这个问题？答案是有，**字节序本质上是"如何解释存储顺序"的问题**，只要两边解释约定不一致就会出错。

观察字节序最直接的办法是把整数强转成字节指针逐个打印：

```c
typedef unsigned char *byte_pointer;

void show_bytes(byte_pointer start, size_t len) {
    for (int i = 0; i < len; i++)
        printf("%.2x\t", start[i]);
}

void show_int(int x) {
    show_bytes((byte_pointer)&x, sizeof(int));
}

int main(void) {
    int x = 0x12345678;
    show_int(x);   // 小端机器输出：78 56 34 12
}
```

## 3. C 语言基本类型的大小

| C 类型 | 32 位 | x86-32 | x86-64 |
|---|---|---|---|
| `char` | 1 | 1 | 1 |
| `short` | 2 | 2 | 2 |
| `int` | 4 | 4 | 4 |
| `long` | 4 | 4 | **8**（Linux） |
| `long long` | 8 | 8 | 8 |
| `float` | 4 | 4 | 4 |
| `double` | 8 | 8 | 8 |
| `long double` | 8 | 10/12 | 10/16 |
| 指针 | 4 | 4 | **8** |

需要记住的差别只有两处：`long` 和指针在 64 位 Linux 上变成 8 字节。写跨平台代码时不要假设 `long` 和 `int` 一样大。

## 4. 整数的编码：无符号数与补码

设字长为 $w$，位串 $X=x_{w-1}x_{w-2}\cdots x_0$。

**无符号数**（课件称为原码表示）就是普通二进制：

$$B2U(X)=\sum_{i=0}^{w-1}x_i\,2^i$$

**带符号数**用补码（Two's Complement），最高位的权重变成负的：

$$B2T(X)=-x_{w-1}\,2^{w-1}+\sum_{i=0}^{w-2}x_i\,2^i$$

最高位 MSB 就是符号位，1 表示负数，0 表示非负数。以 16 位为例，`short x = 12345` 的位串是 `0011 0000 0011 1001`（`0x3039`），`short y = -12345` 的位串是 `1100 1111 1100 0111`（`0xCFC7`）。

**怎么求一个负数的补码**，课件给了两种等价说法：

- 非负数：补码等于原码；负数：补码等于**绝对值按位取反再加 1**，同时也等于 $2^w$ 加上这个负数；
- 一个数的补码，等于它的相反数的补码"按位取反加一"，即 $-x = \sim x + 1$。

一个常见的小题：32 位整数 $X=-101$ 的十六进制补码是多少？$101=\texttt{0x65}$，写成 32 位是 `0x00000065`，取反得 `0xFFFFFF9A`，加 1 得 `0xFFFFFF9B`。

### 为什么补码是这样设计的

课件的解释很干净，只用到一个事实：**在固定位宽 $w$ 的系统里，所有运算都是模 $2^w$ 的。** 于是对任意数 $A$：

$$A+(\sim A+1)=A+(2^w-A)=2^w\equiv 0\pmod{2^w}$$

也就是说 $\sim A+1$ 正好是 $A$ 在模 $2^w$ 下的**加法逆元**，它就应该被当成 $-A$。补码（Two's Complement）这个名字就来源于此。这个设计带来的直接好处是：**加法和减法在电路层面统一**，处理器的运算器只需要一个加法器，不需要为负数另写一套逻辑。

### 取值范围

| | 无符号数 | 带符号数（补码） |
|---|---|---|
| 最小值 | $U_{min}=0$（`00…0`） | $T_{min}=-2^{w-1}$（`10…0`） |
| 最大值 | $U_{max}=2^w-1$（`11…1`） | $T_{max}=2^{w-1}-1$（`01…1`） |
| 特殊值 | — | $-1$ 的位串是 `11…1` |

以 $w=16$ 为例：$U_{max}=65535$（`FFFF`），$T_{max}=32767$（`7FFF`），$T_{min}=-32768$（`8000`），$-1$ 是 `FFFF`。注意负数比正数多一个，$|T_{min}|=T_{max}+1$，所以 $T_{min}$ 没有对应的正数，对它取负还是它自己。

## 5. 同一个位串，两个解读：圆环图

对同一个位串，无符号和有符号的解读差别只在最高位：它的权重一个是 $+2^{w-1}$，一个是 $-2^{w-1}$。所以位串不变时，两种数值之间的转换是：

$$ux=\begin{cases}x & x\ge 0\\ x+2^w & x<0\end{cases}$$

把 4 位整数的 16 种位串排成一个圆环，就能同时看清这件事、以及后面的加减法：

![](/obsidian-assets/612dea094d71a5fc.png)

补码系统的核心，是**把负整数映射到无符号数的高数值区间**：`1000` 到 `1111` 这半圈在无符号看来是 8 到 15，在补码看来是 −8 到 −1。

这个圆环还把加减法解释得很直观。设字长为 $w$，环的周长 $R=2^w$：加 $y$ 就是顺时针走 $y$ 格，减 $y$ 就是逆时针走 $y$ 格，而逆时针走 $y$ 格等价于顺时针走 $R-y$ 格。因此

$$x-y=x+(R-y)=x+(\sim y+1)$$

其中用到 $R-1$ 是全 1 的位串，所以 $R-1-y=\sim y$。**减法就是取反再加一再做加法**，全程只用加法器。

## 6. C 语言里的有符号数与无符号数

在 C 里，两种类型混着用会出现一些让人意想不到的结果，规则有两条：

1. **常量默认是带符号数**，加后缀 `U` 才是无符号数，如 `0U`、`4294967259U`；
2. **有符号数与无符号数混合运算时，有符号数被隐式转换为无符号数**，比较运算符也一样。

下面是课件给出的 $w=32$ 的比较示例，每一行都值得自己推一遍：

| 常量 1 | 常量 2 | 关系 | 按哪种类型比较 | 原因 |
|---|---|---|---|---|
| `0` | `0U` | `==` | 无符号 | 同值 |
| `-1` | `0` | `<` | 有符号 | 都是有符号 |
| `-1` | `0U` | `>` | 无符号 | `-1` 被转成 $U_{max}$ |
| `2147483647` | `-2147483647-1` | `>` | 有符号 | $T_{max}>T_{min}$ |
| `2147483647U` | `-2147483647-1` | `<` | 无符号 | $T_{min}$ 被转成 $2^{31}$ |
| `-1` | `-2` | `>` | 有符号 | 常规比较 |
| `(unsigned)-1` | `-2` | `>` | 无符号 | $U_{max}>U_{max}-1$ |
| `2147483647` | `2147483648U` | `<` | 无符号 | $2^{31}-1<2^{31}$ |
| `2147483647` | `(int)2147483648U` | `>` | 有符号 | 强转后是 $T_{min}$ |

### 什么时候该用无符号数

课件的建议是：**不能仅仅因为取值范围是非负就使用无符号数**；无符号数适合模运算和按位运算。典型的陷阱有两个：

```c
// 示例一：死循环
unsigned i;
for (i = cnt - 2; i >= 0; i--)
    a[i] += a[i + 1];
```

`i` 是无符号数，`i >= 0` 恒成立，`i` 减到 0 之后再减 1 会回绕到 $U_{max}$，循环永远不会退出，还会访问越界。

```c
// 示例二：隐式转换
#define DELTA sizeof(int)
int i;
for (i = CNT; i - DELTA >= 0; i -= DELTA)
    ...
```

`sizeof` 的结果是无符号类型，`i - DELTA` 因此按无符号运算，结果永远不会小于 0，条件恒真。

## 7. 加法、减法与溢出

### 无符号加法

两个 $w$ 位数相加，真实结果可能有 $w+1$ 位，硬件**丢弃进位**，只保留低 $w$ 位：

$$UAdd_w(u,v)=(u+v)\bmod 2^w=\begin{cases}u+v & u+v<2^w\\ u+v-2^w & u+v\ge 2^w\ \text{（溢出）}\end{cases}$$

溢出时结果会"绕回"到小值，因此可以这样判定：**$s=u+v$ 之后，若 $s<u$（或 $s<v$），说明发生了溢出。**

### 补码加法

课件的关键结论是：**补码加法在位模式上与无符号加法完全一致**，用 C 写出来就是

```c
int s, t, u, v;
s = (int)((unsigned)u + (unsigned)v);
t = u + v;
// s == t
```

x86 也确实是这样：有符号和无符号整数加法用的是同一条 `addl` 指令，硬件并不区分。补码加法的正确性可以这样证明，设 $[x]_补$ 为 $x$ 的补码，则 $[x]_补+[y]_补\equiv[x+y]_补\pmod{2^w}$：

- $x>0,\ y>0$：正数的补码就是原码，$x+y>0$，等式显然成立；
- $x>0,\ y<0$ 且 $x+y>0$：$[x]_补=x$，$[y]_补=2^w+y$，相加得 $x+y+2^w\equiv x+y=[x+y]_补$；
- $x>0,\ y<0$ 且 $x+y<0$：同样 $[x]_补+[y]_补=x+y+2^w=[x+y]_补$（负数的补码恰好是 $2^w$ 加它本身）。

### 补码加法的溢出

真实和超出 $[T_{min},T_{max}]$ 时发生溢出，分两种：

$$TAdd_w(u,v)=\begin{cases}u+v+2^w & u+v<T_{min}\ \text{（NegOver，向下溢出）}\\ u+v & T_{min}\le u+v\le T_{max}\\ u+v-2^w & u+v>T_{max}\ \text{（PosOver，向上溢出）}\end{cases}$$

![](/obsidian-assets/1b12b1d73243bafa.png)

判定规则可以总结成三句话：**正加正得到负，是向上溢出；负加负得到正，是向下溢出；一正一负相加，永远不会溢出。**

### 一道填空题

已知 32 位整数 $X=-101$，另一个 32 位整数 $Y$ 的补码是 `0xFFFFFF6A`，求 $X$ 的补码、$X+Y$ 和 $X-Y$ 的补码（课件第 26 页）：

- $X=-101$：`0xFFFFFF9B`（前面算过）；
- $X+Y$：直接按位相加，$\texttt{0xFFFFFF9B}+\texttt{0xFFFFFF6A}=\texttt{0x1FFFFFF05}$，丢弃进位得 `0xFFFFFF05`。（也可以先求 $Y=-150$，则 $X+Y=-251$，补码即 `0xFFFFFF05`）；
- $X-Y$：$-101-(-150)=49$，补码 `0x00000031`。

## 8. 除以 2 的 k 次幂：移位的两副面孔

乘法和一般除法在课程中不要求，但**除以 $2^k$ 要掌握**，因为编译器会把它优化成移位。

### 无符号数：逻辑右移

无符号数右移 $k$ 位，高位补 0，等价于 $\lfloor u/2^k\rfloor$（向零舍入，对非负数也就是向下舍入）。以 $x=15213$（`0x3B6D`）为例：

| 运算 | 精确值 | 结果 | 二进制 |
|---|---|---|---|
| `x >> 1` | 7606.5 | 7606 | `0001 1101 1011 0110` |
| `x >> 4` | 950.8125 | 950 | `0000 0011 1011 0110` |
| `x >> 8` | 59.43… | 59 | `0000 0000 0011 1011` |

对应汇编：`unsigned udiv8(unsigned x) { return x/8; }` 被编译成一条 `shrl $3, %eax`（逻辑右移）。

### 带符号数：算术右移，但有舍入问题

带符号数右移用**算术右移**，高位补符号位，这样负数仍然是负数。但对负数，算术右移得到的是**向下取整**（向 $-\infty$ 舍入），而 C 语言要求整数除法**向 0 舍入**。以 $x=-15213$ 为例：

| 运算 | 精确值 | `x >> k` 的结果 | C 的 `x / 2^k` 应得 |
|---|---|---|---|
| `x >> 1` | −7606.5 | −7607 | −7606 |
| `x >> 4` | −950.81 | −951 | −950 |
| `x >> 8` | −59.43 | −60 | −59 |

所以 `x >> k` 与 `x / 2^k` 在 $x<0$ 且不能整除时**不相等**。解决办法是在右移之前**加一个偏置量**（bias）$2^k-1$，把"向下取整"改成"向上取整"，而 $\lceil x/2^k\rceil=\lfloor (x+2^k-1)/2^k\rfloor$：

```c
(x + (1 << k) - 1) >> k
```

为什么有效，课件分两种情况画了位图：

- **情况一，$x$ 能被 $2^k$ 整除**：低 $k$ 位全是 0，加上 $2^k-1$（低 $k$ 位全 1）之后不会进位到第 $k$ 位，右移后结果不变，偏置不起作用；
- **情况二，$x$ 不能整除**：低 $k$ 位不全为 0，加上 $2^k-1$ 一定会向第 $k$ 位进 1，右移后的结果正好比向下取整多 1，也就是向上取整，对负数来说就是向 0 舍入。

![](/obsidian-assets/1f7b7c3de59244d3.png)

数值验证：$x=-7,\ k=1$，直接右移得 $-4$；加偏置 $(-7+1)>>1=-3$，与 $-7/2=-3$ 一致。

编译器就是这样实现的：`int idiv8(int x) { return x/8; }` 会被编译成

```asm
    testl %eax, %eax      # x 是否为负
    js    L4              # 是负数则跳到 L4
L3:
    sarl  $3, %eax        # 算术右移
    ret
L4:
    addl  $7, %eax        # 负数先加偏置 7 = 2^3 - 1
    jmp   L3
```

等价的 C 描述是：`if (x < 0) x += 7; return x >> 3;`。

## 9. 整数运算的"极端情况"

课件最后让大家判断下面这些推断是否成立（$x,y$ 是 32 位有符号整数，$ux,uy$ 是与它们位串相同的无符号整数）。这些题都只依赖补码的定义，不涉及编译器的具体实现。

| # | 命题 | 结论 | 反例或理由 |
|---|---|---|---|
| 1 | `x < 0` ⇒ `(x*2) < 0` | 假 | $x=T_{min}$ 时 $x\cdot2$ 溢出为 0；$x=\texttt{0xA0000000}$ 时乘 2 之后变成正数 |
| 2 | `ux >= 0` | 真 | 无符号数不可能小于 0 |
| 3 | `(x & 7) == 7` ⇒ `(x << 30) < 0` | 真 | 低 3 位全 1，左移 30 位后，原第 1 位被推到符号位，符号位为 1 |
| 4 | `ux > -1` | 假 | `-1` 被转成 $U_{max}$，没有无符号数大于它 |
| 5 | `x > y` ⇒ `-x < -y` | 假 | $y=T_{min}$ 时 $-y=T_{min}$，而 $x>T_{min}$，$-x<T_{min}$ 不可能 |
| 6 | `x > 0 && y > 0` ⇒ `x + y > 0` | 假 | 两个大正数相加会向上溢出成负数 |
| 7 | `x >= 0` ⇒ `-x <= 0` | 真 | $x\ge0$ 时 $-x\in[-T_{max},0]$，不会溢出 |
| 8 | `x <= 0` ⇒ `-x >= 0` | 假 | $x=T_{min}$ 时 $-x$ 仍是 $T_{min}$，小于 0 |
| 9 | `(x \| -x) >> 31 == -1` | 假 | $x\ne0$ 时 $x$ 与 $-x$ 至少一个为负，结果是 $-1$；$x=0$ 时结果是 0 |
| 10 | `ux >> 3 == ux / 8` | 真 | 逻辑右移就是向零舍入的除法 |
| 11 | `x >> 3 == x / 8` | 假 | 负数且不能被 8 整除时，右移向下取整，如 `-1 >> 3 == -1` 而 `-1 / 8 == 0` |
| 12 | `x & (x-1) != 0` | 假 | $x=0$ 时 $x\&(x-1)=0\&(-1)=0$；2 的幂也满足 `x & (x-1) == 0` |

第 9 题其实是一个有用的小技巧：`(x | -x) >> 31` 在 $x\ne0$ 时恒为 $-1$，在 $x=0$ 时为 0，可以用来在不写分支的情况下判断"是否非零"。第 12 题里 `x & (x-1)` 会清掉最低位的 1，因此它等于 0 当且仅当 $x$ 是 0 或 2 的幂。注意 `!=` 的优先级高于 `&`，上表第 3 题和第 12 题按作者意图加上了括号来读。

## 小结

1. 机器里只有位串；**无符号数与补码是对同一位串的两种解读**，区别仅在最高位的权重是 $+2^{w-1}$ 还是 $-2^{w-1}$。
2. 补码的本质是模 $2^w$ 的加法逆元，所以**加法器不区分有无符号，减法等于取反加一再做加法**。
3. C 语言里**有符号与无符号混合运算会把有符号数隐式转成无符号数**，这是大量比较 bug 和死循环的来源；用无符号数的理由应当是模运算或位运算，而不是"数值非负"。
4. 溢出的判定：无符号看结果是否比操作数小；补码看"正正得负、负负得正"。
5. 除以 $2^k$：无符号用逻辑右移；有符号用算术右移，但负数需要先加偏置 $2^k-1$ 才能与 C 的"向零舍入"一致。

课件在这一讲末尾留下了一个问题：既然硬件层面有符号与无符号加法是同一条 `addl` 指令，那 C 语言层面的"有符号/无符号"语义区别是怎样实现的？答案在第五讲：硬件同时设置两套条件码，由编译器根据类型选择读哪一套（比较时选 `jl` 还是 `jb`），移位时则选 `sar` 还是 `shr`。下一篇讲另一类数——浮点数。
