# 计算机系统概论（四）：汇编入门

> 本篇对应课件第四讲《C 语言的机器表示（一）》（课件标题为"80X86 汇编语言与 C 语言-1"）。前两讲讲的是数据怎么表示，从这一讲开始讲**代码怎么表示**：C 语句被编译之后，在 CPU 眼里是一串什么样的指令。这一讲先学最基本的三件事：数据放在哪里（寄存器与内存）、怎么搬数据（`mov` 与寻址方式）、怎么做计算（算术指令与 `leaq`）。

## 1. 学汇编要掌握什么

课件开头点明了目标：**程序的语义等价转换**，也就是能把一段 C 代码和它对应的汇编互相对上。转换包括基本计算、控制流、循环、函数调用与返回、数组与结构等复合数据的访问，以及代码优化。

在转换过程中，核心的问题可以归结为"定位"：

- **局部变量**放在哪里；
- 条件跳转、无条件跳转的**目的地址**；
- 静态函数的**入口地址**；
- 函数的**返回地址**；
- 函数的**参数与返回值**放在哪里。

这一讲先解决前一部分：数据、参数、返回值怎么用寄存器和内存来表示；课件特别提醒，局部变量并不只能放在寄存器里，学过运行栈之后还会有补充。

## 2. 汇编程序员眼中的计算机

第一讲讲过冯·诺依曼结构。站在汇编层面，它被具体化为下图（课件称之为"控制流架构"）：

![](/obsidian-assets/45e1719ac95db827.png)

CPU 里对程序员**可见**的状态有三类：

- **程序计数器 PC**：存储下一条指令的地址。x86-64 里它的名字是 `%rip`；
- **寄存器堆（register file）**：处理器内部、用名字访问的一组快速存储单元；
- **条件码（condition codes）**：存放最近一条指令执行结果的状态信息，供条件指令（比如条件跳转）使用。

内存是**以字节编码的连续存储空间**，里面放着用户程序的代码与数据、栈（Stack）、堆（Heap），也包括操作系统的代码与数据。CPU 与内存之间有三类流动：地址、数据、指令。

### 寄存器与内存的区别

| 项目 | 寄存器 | 内存 |
|---|---|---|
| 位置 | CPU 内部 | CPU 外部 |
| 访问速度 | 快 | 慢 |
| 容量 | 小 | 大 |
| 成本 | 高 | 低 |
| 表示方式 | 用**名字**表示 | 用**地址**表示 |
| 地址 | 没有 | 可用多种方式形成（多种内存寻址方式） |

课件在这里补充了一张延迟表（对比了 Intel、Apple M4、AMD Zen 5 等几代处理器），数量级需要记住：L1 缓存约 3–4 个周期，L2 约 10–28 个周期，L3（Apple 芯片上是系统级缓存 SLC）约 40–120 个周期，而主存 DRAM 约 **100 个周期以上**。寄存器就在 CPU 内部，访问几乎没有额外延迟，这就是为什么编译器要尽量把变量放在寄存器里。

## 3. 从 C 代码到汇编代码

课件用一个很小的函数来演示：

```c
long plus(long x, long y);

void sumstore(long x, long y, long *dest)
{
    long t = plus(x, y);
    *dest = t;
}
```

生成汇编的命令是 `gcc -Og -S sum.c`，得到 `sum.s`：

```asm
sumstore:
    pushq %rbx
    movq  %rdx, %rbx
    call  plus
    movq  %rax, (%rbx)
    popq  %rbx
    ret
```

几个命令和它们的产物对应关系：

| 命令 | 产物 |
|---|---|
| `gcc -Og -S sum.c` | `sum.s`，汇编文本 |
| `gcc -Og -c sum.c` | `sum.o`，目标文件，里面是机器指令 |
| `objdump -d sum.o` | 反汇编目标文件 |
| `gdb sum` 然后 `disassemble sumstore` | 反汇编某个函数 |
| `x/14xb sumstore` | 以 16 进制字节形式查看从 `sumstore` 开始的 14 个字节 |

反汇编的结果把"地址、机器码、汇编"并排列出来：

```text
0000000000400595 <sumstore>:
  400595:  53                 push   %rbx
  400596:  48 89 d3           mov    %rdx,%rbx
  400599:  e8 f2 ff ff ff     callq  400590 <plus>
  40059e:  48 89 03           mov    %rax,(%rbx)
  4005a1:  5b                 pop    %rbx
  4005a2:  c3                 retq
```

注意这里：`*dest = t;` 这一行 C 代码对应的机器指令是 `mov %rax,(%rbx)`，机器码只有三个字节 `48 89 03`，它自己位于地址 `0x40059e`。机器指令是**变长**的，这一点在最后一节会再提。课程为 gdb 等工具安排了专门课时。

## 4. 汇编语言的基本特点

**数据类型**很少：

- 整型：宽度 1、2、4、8 字节，用来表示数值，也用来表示内存**地址**；
- 浮点：宽度 4、8 或 10 字节；
- **没有复合数据类型**：数组、结构在汇编里不存在，它们只是内存里连续分配的若干字节，怎么解释由编译器决定。

**操作类型**只有三类：

- 对寄存器或内存数据做算术、逻辑运算；
- 在内存与寄存器之间、寄存器与寄存器之间传送数据（内存读入寄存器、寄存器写回内存）；
- 转移控制：无条件跳转、函数调用与返回、条件跳转。

课件使用的是 **AT&T 语法**：**源操作数在前，目的操作数在后**；立即数前加 `$`；寄存器前加 `%`；指令名带一个**大小后缀**：

| 后缀 | 含义 | 宽度 |
|---|---|---|
| `b` | byte | 1 字节（8 位） |
| `w` | word | 2 字节（16 位） |
| `l` | long（双字） | 4 字节（32 位） |
| `q` | quadword（四字） | 8 字节（64 位） |

这里有一个容易混淆的地方：x86 沿用历史习惯，"字"（word）指 16 位，所以 32 位叫"双字"、64 位叫"四字"，与前面讲过的"机器字长"不是一回事。汇编指令处理的数据宽度，是靠**指令后缀**区分的。

## 5. 寄存器

x86-64 有 **16 个通用寄存器**，每个都可以用不同位宽的名字访问：

| 64 位 | 32 位 | 64 位 | 32 位 |
|---|---|---|---|
| `%rax` | `%eax` | `%r8` | `%r8d` |
| `%rdx` | `%edx` | `%r9` | `%r9d` |
| `%rcx` | `%ecx` | `%r10` | `%r10d` |
| `%rbx` | `%ebx` | `%r11` | `%r11d` |
| `%rsi` | `%esi` | `%r12` | `%r12d` |
| `%rdi` | `%edi` | `%r13` | `%r13d` |
| `%rsp` | `%esp` | `%r14` | `%r14d` |
| `%rbp` | `%ebp` | `%r15` | `%r15d` |

![](/obsidian-assets/ede45ae4458fa932.png)

x86-32 时代的寄存器只有 8 个，名字带有历史用途：`%eax` 累加器（accumulate）、`%ecx` 计数器（counter）、`%edx` 数据（data）、`%ebx` 基址（base）、`%esi` 源变址（source index）、`%edi` 目的变址（destination index）、`%esp` 栈指针（stack pointer）、`%ebp` 基指针（base pointer）；其中前四个还能拆出 16 位和 8 位的名字（`%ax`、`%ah`、`%al` 等）。这些原始用途现在基本已经过时，但这些名字被保留了下来。

在 x86-64 下，**`%rsp` 有特殊用途**（栈指针，后面讲函数调用时会用到），其他某些寄存器在特定指令里也有特定用途。

## 6. 数据传送：`mov`

最基本的指令是 `movq Source, Dest`（以 8 字节为例），把源操作数复制到目的操作数。操作数有三种类型：

- **立即数**：整型常数，加 `$` 前缀，如 `$0x400`、`$-533`，宽度可以是 1、2、4、8 字节；
- **寄存器**：16 个通用寄存器之一，如 `%rax`、`%r13`；
- **内存**：起始于某个地址的连续字节，地址由地址表达式给出，最简单的例子是 `(%rax)`。

`mov` 支持的组合（源，目的）和对应的 C 语言：

| 源 | 目的 | 汇编示例 | 类似的 C 语言 |
|---|---|---|---|
| 立即数 | 寄存器 | `movq $0x4,%rax` | `temp = 0x4;` |
| 立即数 | 内存 | `movq $-147,(%rax)` | `*p = -147;` |
| 寄存器 | 寄存器 | `movq %rax,%rdx` | `temp2 = temp1;` |
| 寄存器 | 内存 | `movq %rax,(%rdx)` | `*p = temp;` |
| 内存 | 寄存器 | `movq (%rax),%rdx` | `temp = *p;` |

**不能两个操作数都是内存。** 要把一个内存单元搬到另一个内存单元，必须先读入寄存器，再写出去。对照 C 语言可以发现：`*p` 这样的指针解引用，在汇编里就是"用寄存器里的值当作地址去访问内存"。

## 7. 寻址模式

内存地址表达式有多种形式，统一的一般形式是：

$$\text{Mem}[\,Reg[R_b]+S\times Reg[R_i]+D\,]\qquad\text{写作 }D(R_b,R_i,S)$$

其中 $D$ 是常数偏移量，$R_b$ 是基址寄存器（16 个通用寄存器之一），$R_i$ 是变址（索引）寄存器（**`%rsp` 不能作为索引寄存器**），$S$ 是比例因子，只能取 1、2、4、8。其余形式都是它的特例：

| 形式 | 名称 | 内存地址 |
|---|---|---|
| `(R)` | 间接寻址 | $Mem[Reg[R]]$ |
| `D(R)` | 基址 + 偏移量 | $Mem[Reg[R]+D]$ |
| `(Rb,Ri)` | | $Mem[Reg[R_b]+Reg[R_i]]$ |
| `D(Rb,Ri)` | | $Mem[Reg[R_b]+Reg[R_i]+D]$ |
| `(Rb,Ri,S)` | | $Mem[Reg[R_b]+S\times Reg[R_i]]$ |
| `D(Rb,Ri,S)` | 变址模式（完整形式） | $Mem[Reg[R_b]+S\times Reg[R_i]+D]$ |

设 `%rdx = 0xf000`，`%rcx = 0x0100`，课件给出了四个计算示例：

| 地址表达式 | 地址计算 | 结果 |
|---|---|---|
| `0x8(%rdx)` | `0xf000 + 0x8` | `0xf008` |
| `(%rdx,%rcx)` | `0xf000 + 0x100` | `0xf100` |
| `(%rdx,%rcx,4)` | `0xf000 + 4*0x100` | `0xf400` |
| `0x80(,%rdx,2)` | `2*0xf000 + 0x80` | `0x1e080` |

### 怎么读这些括号

学汇编最容易卡住的就是这一步：同样是括号，里面有时一项、有时两项、有时三项，甚至开头出现 `(,%rdx,2)` 这样的空位。其实规则只有一条，**括号外面的是常数，括号里按顺序是"基址寄存器，变址寄存器，比例因子"**，用逗号隔开：

![](/obsidian-assets/9a3832edfec52303.png)

- 最后算出的**有效地址** = 括号外的常数 $D$ + 基址寄存器的值 + 比例因子 $S$ × 变址寄存器的值；
- **缺哪一项，哪一项就取"不起作用"的值**：没写 $D$ 当作 0，没写 $S$ 当作 1，没写基址或变址寄存器就当作 0；
- 逗号是用来**定位**的，所以省掉基址寄存器时要保留逗号，写成 `3(,%rdi,8)`，意思是"没有基址，变址是 `%rdi`，比例是 8，常数是 3"，即地址 $= 8\times\text{Reg}[\%rdi]+3$；
- 括号里只有一个寄存器，如 `(%rdi)`，就是把这个寄存器当作地址（也就是 C 里的 `*p`）；
- 括号里有两个寄存器而没有比例因子，如 `(%rdi,%rsi)`，是两个寄存器的值直接相加，因为 $S$ 缺省为 1；
- 括号里有三项，如 `(%rdi,%rsi,4)`，第二个寄存器的值要先乘以 4 再相加。

**这些括号本身只是在描述"一个地址是怎么算出来的"，不一定意味着访问内存。**是否访问内存，由用它的指令决定：`movq` 会拿算出的地址去读写内存；下面第 9 节的 `leaq` 则只计算、不访问。

这种形式之所以设计得这么复杂，是为了直接对应 C 里的数组和结构访问：`D(Rb,Ri,S)` 的 $S$ 正好可以是 `int`、`long` 等元素的宽度。比如 `long a[]`，要访问 `a[i]`，基址放 `a` 的首地址，索引放 `i`，比例因子取 8，一条指令就够了。这些在后面讲数组时会反复出现。

## 8. 完整例子：`swap`

```c
void swap(long *xp, long *yp)
{
    long t0 = *xp;
    long t1 = *yp;
    *xp = t1;
    *yp = t0;
}
```

```asm
swap:
    movq (%rdi), %rax    # t0 = *xp
    movq (%rsi), %rdx    # t1 = *yp
    movq %rdx, (%rdi)    # *xp = t1
    movq %rax, (%rsi)    # *yp = t0
    ret
```

**参数怎么传进来？** 约定是：参数少于 7 个时，从左到右依次放入寄存器 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`；7 个及以上时，前 6 个仍放寄存器，**后面的从右到左依次压入栈中**。**返回值放在 `%rax`。** 所以这里 `%rdi` 是第一个参数 `xp`，`%rsi` 是第二个参数 `yp`，都是 64 位宽的指针，局部变量 `t0`、`t1` 被编译器分配到了 `%rax` 和 `%rdx`。

下面逐步跟踪执行过程。设 `xp = 0x120`，`yp = 0x100`，内存中 `M[0x120] = 123`，`M[0x100] = 456`：

![](/obsidian-assets/c9ed610c9b9275ee.png)

| 步骤 | 执行的指令 | `%rax` | `%rdx` | `M[0x120]` | `M[0x100]` |
|---|---|---|---|---|---|
| 初始 | — | — | — | 123 | 456 |
| 1 | `movq (%rdi), %rax` | **123** | — | 123 | 456 |
| 2 | `movq (%rsi), %rdx` | 123 | **456** | 123 | 456 |
| 3 | `movq %rdx, (%rdi)` | 123 | 456 | **456** | 456 |
| 4 | `movq %rax, (%rsi)` | 123 | 456 | 456 | **123** |

最终状态：

![](/obsidian-assets/5190bfa22d693d39.png)

整个过程中，**内存只被访问了 4 次**，中间量都放在寄存器里。这里也能看出"为什么不能 mem 到 mem"：交换两个内存单元，必须借助寄存器才能完成。

如果换成 `int` 版本，指针依然是 64 位，仍然用 `%rdi`、`%rsi` 传递；但被操作的数据是 32 位，所以使用 32 位寄存器 `%eax`、`%edx` 和后缀为 `l` 的指令：

```asm
swap:
    movl (%rdi), %edx
    movl (%rsi), %eax
    movl %eax, (%rdi)
    movl %edx, (%rsi)
    retq
```

## 9. 地址计算指令 `leaq`

`leaq` 是 "load effective address"（装入有效地址）的缩写，名字容易让人以为它在"装入"什么。它的实际行为可以用一句话说清：

> **`leaq Src, Dest`：把 `Src` 这个地址表达式算出来的结果（那个地址值本身）放进寄存器 `Dest`，不访问内存。**

### 9.1 与 `movq` 对比

两条指令用的是同样的地址表达式（第 7 节讲的 `D(Rb,Ri,S)`），区别只在于算出地址之后做什么。设 `%rax = 0x1000`，`%rbx = 3`，内存地址 `0x100c` 处存着 `0x77`，则地址表达式 `(%rax,%rbx,4)` 的值是 $0x1000+4\times3=0x100c$：

| 指令 | 做了什么 | 结果 |
|---|---|---|
| `movq (%rax,%rbx,4), %rdx` | 算出地址 `0x100c`，**去内存里读**那里的 8 字节 | `%rdx = 0x77` |
| `leaq (%rax,%rbx,4), %rdx` | 算出地址 `0x100c`，**直接把这个数放进** `%rdx` | `%rdx = 0x100c` |

所以，`leaq` 的源操作数写成"内存操作数"的样子（带括号），但它**只是借用了这套写法来表达一个算式**，没有任何内存访问。

### 9.2 第一种用法：取地址

对应 C 里的 `&`：

```c
long *get_ptr(long *a, long i) { return &a[i]; }
```

```asm
# %rdi = a（数组首地址），%rsi = i
leaq (%rdi,%rsi,8), %rax      # %rax = a + 8*i，即 &a[i]
```

`long` 占 8 字节，所以第 $i$ 个元素的地址是 $a+8i$：基址是 `%rdi`，变址是 `%rsi`，比例因子取元素大小 8。这条指令只是算出了这个地址，并没有去读 `a[i]` 的内容。若要读取内容，就要用 `movq (%rdi,%rsi,8), %rax`。

### 9.3 第二种用法：做整数计算

既然 `leaq` 能算 $D+R_b+S\times R_i$ 这个式子，把"地址"当成普通整数也一样，**只要算式恰好是这个形状，就可以拿它做加法和乘法**。编译器很爱这样用，因为：

- 一条指令可以同时完成"两个寄存器相加、一个乘 1/2/4/8、再加一个常数"，且**源寄存器不会被改写**（`addq` 会覆盖目的寄存器，`leaq` 的结果可以放在另一个寄存器里）；
- 它**不会改变条件码**（第五讲会讲），不影响后面的比较与跳转。

对照下面这张表读，就能认出 `leaq` 的各种写法：

| C 表达式 | 汇编 | 怎么读 |
|---|---|---|
| `x + y` | `leaq (%rdi,%rsi), %rax` | 两个寄存器直接相加，$S$ 缺省为 1 |
| `x + y + 7` | `leaq 7(%rdi,%rsi), %rax` | 在上面基础上再加常数 7 |
| `x + 4*y` | `leaq (%rdi,%rsi,4), %rax` | 基址 $x$，变址 $y$，$y$ 先乘 4 |
| `8*x + 3` | `leaq 3(,%rdi,8), %rax` | 没有基址（逗号前留空），所以只有 $8x$，再加 3 |
| `x + 8*y + 12` | `leaq 12(%rdi,%rsi,8), %rax` | 三项全用：$12+x+8y$ |
| `3*x` | `leaq (%rdi,%rdi,2), %rax` | 基址和变址是**同一个寄存器**：$x+2x=3x$ |
| `5*x` | `leaq (%rdi,%rdi,4), %rax` | $x+4x=5x$ |
| `9*x` | `leaq (%rdi,%rdi,8), %rax` | $x+8x=9x$ |

（以上假设 `x` 在 `%rdi`，`y` 在 `%rsi`，这些都是用 gcc 编译对应的 C 函数得到的结果。）

最后三行是理解 `leaq` 的关键：**把同一个寄存器同时当作基址和变址**，得到"自己加上自己的若干倍"，也就是 $1+S$ 倍。因为 $S$ 只能是 1、2、4、8，所以这种写法一条 `leaq` 只能乘以 2、3、5、9。

### 9.4 例：`x * 12`

```c
long m12(long x) { return x * 12; }
```

```asm
leaq (%rdi,%rdi,2), %rax   # t = x + x*2 = 3x
salq $2, %rax              # return t << 2 = 12x
```

12 不能写成 $1+S$（$S$ 只能是 1、2、4、8），所以一条 `leaq` 做不到。编译器把它拆成 $12=3\times4$：先用 `leaq` 算 $3x$，再左移 2 位乘以 4。这样既避免了较慢的乘法指令，也只用了两条简单指令。

### 9.5 使用时的几条规则

- `leaq` 的**源操作数必须是内存操作数的形式**（带括号的地址表达式）；**目的操作数必须是寄存器**。`leaq %rax, %rbx` 是不合法的；
- 比例因子 $S$ 只能取 1、2、4、8；
- `q` 后缀表示 64 位。对 32 位的 `int` 运算，编译器会用 `leal`，目的寄存器用 `%eax` 这类 32 位寄存器，例如 `int f(int x,int y){return x+y;}` 会被编译成 `leal (%rdi,%rsi), %eax`。

## 10. 整数运算指令

**双操作数指令**，形式为 `op Src, Dest`，结果写回 `Dest`：

| 指令 | 操作 | 说明 |
|---|---|---|
| `addq Src,Dest` | `Dest = Dest + Src` | |
| `subq Src,Dest` | `Dest = Dest - Src` | |
| `imulq Src,Dest` | `Dest = Dest * Src` | 乘法，取低 64 位 |
| `salq Src,Dest` | `Dest = Dest << Src` | 左移，与 `shlq` 等价 |
| `sarq Src,Dest` | `Dest = Dest >> Src` | **算术**右移 |
| `shrq Src,Dest` | `Dest = Dest >> Src` | **逻辑**右移 |
| `xorq Src,Dest` | `Dest = Dest ^ Src` | |
| `andq Src,Dest` | `Dest = Dest & Src` | |
| `orq Src,Dest` | `Dest = Dest \| Src` | |

**单操作数指令**：

| 指令 | 操作 |
|---|---|
| `incq Dest` | `Dest = Dest + 1` |
| `decq Dest` | `Dest = Dest - 1` |
| `negq Dest` | `Dest = -Dest` |
| `notq Dest` | `Dest = ~Dest` |

注意 `sarq` 与 `shrq` 是**两条不同的指令**。联系第二讲留下的那个问题：同一条 `addl` 既做有符号加法也做无符号加法，硬件不区分；但**右移**就必须区分，`sarq` 补符号位，`shrq` 补 0。这就是 C 里 `int` 与 `unsigned` 的语义差别在汇编里的体现之一，编译器要根据变量的类型来**选择不同的指令**。其余的区别（比较与跳转）留到下一讲。

### 例：用这些指令翻译一个函数

```c
long arith(long x, long y, long z)
{
    long t1 = x + y;
    long t2 = z + t1;
    long t3 = x + 4;
    long t4 = y * 48;
    long t5 = t3 + t4;
    long rval = t2 * t5;
    return rval;
}
```

```asm
arith:
    leaq  (%rdi,%rsi), %rax      # t1 = x + y
    addq  %rdx, %rax             # t2 = z + t1
    leaq  (%rsi,%rsi,2), %rdx    # 3y
    salq  $4, %rdx               # t4 = 3y * 16 = 48y
    leaq  4(%rdi,%rdx), %rcx     # t5 = x + 4 + t4
    imulq %rcx, %rax             # rval = t2 * t5
    ret
```

| 寄存器 | 用途 |
|---|---|
| `%rdi` | 参数 `x` |
| `%rsi` | 参数 `y` |
| `%rdx` | 参数 `z`，之后复用作 `t4` |
| `%rax` | `t1`、`t2`、`rval` |
| `%rcx` | `t5` |

逐条看这几个 `leaq`（`x`、`y`、`z` 分别在 `%rdi`、`%rsi`、`%rdx`）：

| 指令 | 括号怎么读 | 结果 |
|---|---|---|
| `leaq (%rdi,%rsi), %rax` | 基址 `%rdi`，变址 `%rsi`，$S=1$，无常数 | $x+y$，即 `t1` |
| `leaq (%rsi,%rsi,2), %rdx` | 基址、变址都是 `%rsi`，$S=2$ | $y+2y=3y$ |
| `leaq 4(%rdi,%rdx), %rcx` | 常数 4，基址 `%rdi`，变址 `%rdx`（此时存着 $48y$） | $x+48y+4$，即 `t5` |

课件问了一个问题："`t3` 去哪了？"答案是：`t3 = x + 4` 被**合并进了** `leaq 4(%rdi,%rdx), %rcx` 里的偏移量 4，所以汇编里根本没有出现 `t3` 这个量；同样，`t1`、`t2`、`rval` 共用 `%rax`，因为它们的生命期不重叠。这是编译器做的最基本的优化，同时也说明**汇编里的"变量"和 C 里的变量不是一一对应的**。

### 两道练习

**练习一**（课件第 37 页的填空）：

```c
long arith2(long x, long y, long z)
{
    long t1 = x + z + y;
    long t3 = x + 4;
    long t4 = y * 48;
    long t5 = t3 + t4;
    long rval = t1 * t5;
    return rval;
}
```

```asm
arith2:
    leaq  (%rdi,%rdx), %rax        # x + z
    addq  [填空1], %rax            # + y
    leaq  (%rsi,%rsi,[填空2]), %rdx
    salq  $4, %rdx
    leaq  4(%rdi,%rdx), [填空3]
    imulq %rdx, %rax
    ret
```

- 填空 1：此时 `%rax` 里是 `x+z`，还要加上 `y`，`y` 在 `%rsi`，所以填 **`%rsi`**；
- 填空 2：`y*48 = (y*3)*16`，先用 `leaq` 算 `y + 2*y = 3y`，比例因子是 **2**；
- 填空 3：最后一条 `imulq %rdx, %rax` 用的是 `%rdx` 作乘数，说明 `t5` 必须放在 `%rdx`，所以填 **`%rdx`**（把前面 `%rdx` 里的 `t4` 覆盖掉）。

**练习二**（逻辑运算）：

```c
int logical(int x, int y)
{
    int t1 = x ^ y;
    int t2 = t1 >> 17;
    int mask = (1 << 13) - 7;
    int rval = t2 & mask;
    return rval;
}
```

```asm
logical:
    movl  %edi, %eax
    xorl  %esi, %eax      # t1 = x ^ y
    sarl  $17, %eax       # t2 = t1 >> 17（有符号，所以是算术右移）
    andl  $8185, %eax     # mask = 2^13 - 7 = 8192 - 7 = 8185
    ret
```

这里的细节：`mask` 是编译期就能算出的常量 $2^{13}-7=8185$，被直接写成了立即数；`int` 是 32 位，所以用 `%edi`、`%esi`、`%eax` 与 `l` 后缀；`x`、`y` 是有符号数，所以右移是 `sarl`。

## 11. x86-64 指令集的特点

课件在最后总结了几条：

- **支持多种类型的指令操作数**：立即数、寄存器、内存数据；
- **支持多种内存地址计算方式**，即 $R_b+S\times R_i+D$，这套机制也可以通过 `leal`、`leaq` 用于整数运算；
- **算术逻辑指令可以直接以内存数据为操作数**；
- **指令是变长的**，长度 1 到 15 个字节。

这些都是 CISC（复杂指令集）的特点，与 RISC-V 这样的精简指令集形成对比。

## 小结

1. 汇编层面的机器 = **PC + 寄存器堆 + 条件码 + 内存**；寄存器用名字访问、速度快、容量小，内存用地址访问、速度慢、容量大。
2. AT&T 语法：**源在前、目的在后**，`$` 表示立即数，`%` 表示寄存器，后缀 `b/w/l/q` 表示 1/2/4/8 字节。
3. `mov` 的操作数可以是立即数、寄存器、内存，但**不能内存到内存**；C 里的指针解引用对应"寄存器里的值当作地址"。
4. 内存寻址的一般形式是 $D(R_b,R_i,S)$，对应地址 $R_b+S\times R_i+D$，是为数组和结构访问量身设计的。
5. 函数参数依次放在 `%rdi, %rsi, %rdx, %rcx, %r8, %r9`，更多的放栈，返回值放 `%rax`。
6. `leaq` 只算地址不访存，常被用作 $x+k\times y$ 的整数运算；`sarq` 与 `shrq` 说明 C 的类型语义要靠**选择不同的指令**来体现。
