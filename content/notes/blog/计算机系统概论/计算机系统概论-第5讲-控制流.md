# 计算机系统概论（五）：控制流

> 本篇对应课件第五讲《C 语言的机器表示（二）》（课件标题为"80X86 汇编语言与 C 语言-2"）。上一篇里指令都是顺着执行的，这一篇要解决：**C 里的判断和循环，在 CPU 上是怎么实现的**。它同时回答第二讲留下的那个问题：有符号和无符号的语义区别，究竟由谁来完成。

## 1. 控制流

处理器从启动到关闭只做一件事：**读取并执行一个指令序列，一次一条**。这个执行的顺序，叫做 CPU 的**控制流**。

默认情况下控制流是顺序的，改变它有两种机制：

- **无条件跳转（jump）与条件跳转（branch）**：本篇讲；
- **过程调用与返回（call / return）**：下一篇讲。

x86-64 的处理器状态中，与控制流直接相关的是：`%rip`（当前指令的下一条地址，即 PC）、`%rsp`（栈顶地址）、一般寄存器里的临时数据，以及四个**条件码**：`CF`、`ZF`、`SF`、`OF`。

## 2. 条件码

条件码是 CPU 内部的几个 1 位的标志位，由**算术指令隐含地设置**，记录"最近一次运算的结果有什么特征"，供后面的条件指令读取。

| 标志 | 名称 | 置 1 的条件 |
|---|---|---|
| `CF` | 进位/借位标志 | 无符号运算产生进位（或减法产生借位），用来检测**无符号**整数运算的溢出 |
| `ZF` | 零标志 | 结果为 0 |
| `SF` | 符号标志 | 结果小于 0（即最高位为 1） |
| `OF` | 溢出标志 | 补码运算溢出，即**带符号**整数运算溢出 |

以 `addq Src, Dest`（`t = a + b`）为例：

- `CF`：有进位则置 1；
- `ZF`：`t == 0` 则置 1；
- `SF`：`t < 0` 则置 1；
- `OF`：补码溢出则置 1，条件是 `(a>0 && b>0 && t<0) || (a<0 && b<0 && t>=0)`，也就是第二讲讲的"正正得负、负负得正"。

**`leaq` 指令不设置条件码**，因为它做的是地址计算，不是算术运算。

两点提醒：第一，条件码是"最近一次算术运算"的记录，**下一条算术指令执行后就会被覆盖**，所以比较和跳转必须紧挨着写；第二，这四个标志是**硬件对同一个结果同时记下的四种观察**，不管程序员心里把这些数当作有符号数还是无符号数，硬件都一并记录，由后面的指令决定读哪几个。

### 用 8 位数把四个标志看一遍

为了看得清楚，取 8 位加法（`addb`），一共四个标志。回忆第二讲：8 位无符号数范围是 0～255，8 位补码范围是 −128～127，超出范围就是"溢出"，结果等于模 256 回绕后的值。

| 运算 | 8 位结果 | 无符号看 | 有符号看 | CF | ZF | SF | OF |
|---|---|---|---|---|---|---|---|
| `0x01 + 0x02` | `0x03` | 1+2=3 | 1+2=3 | 0 | 0 | 0 | 0 |
| `0x7F + 0x01` | `0x80` | 127+1=128，没超出 | 127+1=128，**超出 127**，回绕成 −128 | 0 | 0 | 1 | **1** |
| `0xFF + 0x01` | `0x00` | 255+1=256，**超出 255**，回绕成 0 | (−1)+1=0，没超出 | **1** | 1 | 0 | 0 |
| `0x80 + 0x80` | `0x00` | 128+128=256，**超出** | (−128)+(−128)=−256，**超出** | **1** | 1 | 0 | **1** |

对照着读：

- **`CF` 盯的是"无符号数是否算超出了范围"**：加法时就是"最高位向前产生了进位"（256 这个 1 进到了第 9 位，被丢掉了）；
- **`OF` 盯的是"补码是否算超出了范围"**：第 2 行 127+1 在无符号里完全正常，在补码里却变成了负数，`OF=1`；第 3 行反过来，无符号溢出而补码没有溢出；
- **`ZF` 看结果的每一位是不是全 0；`SF` 就是结果的最高位**；
- 同一个结果、同样的位，无符号和有符号两种解读可以得出完全不同的结论，因此硬件要把 `CF` 和 `OF` 两套都记下来。

### 比较指令 `cmp`

```asm
cmpq Src2, Src1        # 计算 Src1 - Src2，但不保存结果
```

注意 AT&T 语法的次序：`cmpq b, a` 计算的是 **`a - b`**，只用来设置条件码，**不改变任何操作数**。设置规则：

- `CF`：最高位有借位则置 1（可用于无符号数比较）；
- `ZF`：`a == b` 则置 1；
- `SF`：`a - b < 0` 则置 1；
- `OF`：补码减法溢出则置 1，条件是 `(a>=0 && b<0 && (a-b)<0) || (a<0 && b>0 && (a-b)>0)`。

**为什么比较大小要用"减法"？** 比较 $a$ 和 $b$，其实就是看 $a-b$ 是正、零还是负：`ZF=1` 就是相等；结果为负（`SF`）、或无符号时向高位借了位（`CF`），就是 $a$ 比 $b$ 小。比较只需要这些信息，不需要差值本身，所以 `cmp` 把差值丢掉，只留条件码。`test` 同理，只是把减法换成按位与。

在做 `cmp` 时，`CF` 的含义是**借位**：无符号数里 $a<b$，就需要向更高位借 1 才能减，所以 $a<b$（无符号）等价于 `CF=1`。

看两个 8 位的例子（`cmpb b, a` 即计算 $a-b$）：

| $a$ | $b$ | 差 | CF | ZF | SF | OF |
|---|---|---|---|---|---|---|
| `0x03` | `0x05` | `0xFE` | 1（3 < 5，要借位） | 0 | 1 | 0 |
| `0x80` | `0x01` | `0x7F` | 0（128 ≥ 1，不借位） | 0 | 0 | **1** |

第二行很有意思：同样的位，作为**无符号**数是 128 比 1，$a>b$（`CF=0`，所以 `ja` 成立）；作为**补码**则是 −128 比 1，显然 $a<b$。这里差值 `0x7F` 的符号位是 0，似乎说明"不小于"，但 −128−1=−129 超出了范围，回绕成了 127，所以 `OF=1` 提示"符号位说了谎"。下一节会看到，有符号的 `jl` 正是把 `SF` 和 `OF` 异或起来，用 `OF` 去纠正这个谎。

### 测试指令 `test`

```asm
testq Src2, Src1       # 计算 Src1 & Src2，但不保存结果
```

设置规则：`ZF`：`Src1 & Src2 == 0` 则置 1；`SF`：结果小于 0 则置 1；`CF` 与 `OF` 被清为 0。最常见的写法是 `testq %rax, %rax`，用同一个寄存器自己与自己做 `&`，结果就是它本身，于是 `ZF` 表示"是否为 0"，`SF` 表示"是否为负"。第二讲里 `x/8` 的汇编里出现的 `testl %eax, %eax` 加 `js` 就是这个用法。

## 3. 读取条件码：`setX` 与 `jX`

条件码本身不能直接参与运算，要靠两类指令读出来：

- **`setX`**：读取某个条件（若干条件码的组合），把 0 或 1 写入一个**字节寄存器**，其余 7 个字节不变；
- **`jX`**：根据条件决定是否跳转，**不满足条件则顺序执行下一条**。

两者的条件是一一对应的：

| `setX` / `jX` | 条件码组合 | 含义 |
|---|---|---|
| `sete` / `je` | `ZF` | 相等 / 为零 |
| `setne` / `jne` | `~ZF` | 不相等 / 非零 |
| `sets` / `js` | `SF` | 负数 |
| `setns` / `jns` | `~SF` | 非负数 |
| `setg` / `jg` | `~(SF^OF) & ~ZF` | 大于（**有符号**） |
| `setge` / `jge` | `~(SF^OF)` | 大于等于（有符号） |
| `setl` / `jl` | `SF^OF` | 小于（有符号） |
| `setle` / `jle` | `(SF^OF) \| ZF` | 小于等于（有符号） |
| `seta` / `ja` | `~CF & ~ZF` | 高于（**无符号**） |
| `setb` / `jb` | `CF` | 低于（无符号） |
| — / `jmp` | 1 | 无条件跳转 |

读这张表有个窍门：助记符里的字母是英文缩写。`e` 是 equal，`ne` 是 not equal，`s` 是 sign（负号），`g`、`l` 是 greater、less（**有符号**的大于、小于），`a`、`b` 是 above、below（**无符号**的高于、低于）。`cmp b, a` 之后紧跟的 `jX` 一律读作"**a 与 b 的关系**"：例如 `cmpq %rsi, %rdi` 后接 `jle`，就是"`%rdi` ≤ `%rsi` 则跳转"，次序别读反。

`setX` 的目的寄存器是字节寄存器（`%al`、`%bl`、`%sil`、`%r8b` 等，其中 `%al` 就是 `%rax` 的最低一个字节，第四讲的寄存器表里列过），**只会写这一个字节，`%rax` 的其余 7 个字节保持原样**。如果原来 `%rax` 里是一个很大的数，只写 `%al` 之后整个 `%rax` 仍然不是干净的 0 或 1。所以通常紧接着用 **`movzbl`** 把这个字节零扩展成 32 位（同时 32 位写入会把 `%rax` 高 32 位清零，见第 9 节）。例子：

```c
int gt(long x, long y) { return x > y; }
```

```asm
cmpq   %rsi, %rdi      # 比较 x:y，即计算 x - y
setg   %al             # x > y（有符号）时置 1
movzbl %al, %eax       # 把 %al 零扩展到 %eax（同时清零 %rax 的高 32 位）
ret
```

### 有符号与无符号：同一条 `cmp`，不同的 `jX`

这里就是第二讲末尾那个问题的答案。硬件在做 `cmp`（也包括 `add`）时**并不知道**操作数是有符号还是无符号，它同时设置 `CF` 和 `OF` 两套标志；**C 语言类型的语义，是通过编译器选择读取哪一组标志来体现的**：

- 比较**有符号**数，用 `jg / jge / jl / jle`、`setg / setl` 等，读 `SF`、`OF`、`ZF`；
- 比较**无符号**数，用 `ja / jb`、`seta / setb` 等，读 `CF`、`ZF`。

可以用 gcc 亲自验证：

```c
int lt_s(long a, long b)           { return a < b; }   // 编译成 cmpq + setl
int lt_u(unsigned long a, unsigned long b) { return a < b; }   // 编译成 cmpq + setb
```

两个函数的 `cmpq %rsi, %rdi` 完全一样，差别只在后面是 `setl` 还是 `setb`。

**为什么有符号的"小于"是 `SF^OF`、无符号的"小于"是 `CF`？** 设 `cmp` 计算 $t=a-b$（模 $2^w$）：

- **无符号**：$a<b$ 时，减法需要向更高位借位，所以 `CF = 1`，这就是 `jb` 的条件；
- **有符号**，分三种情况：
  1. 没有溢出：$a<b\iff t<0\iff SF=1$，此时 $OF=0$，所以 $SF\oplus OF=1$；
  2. 正溢出（$a\ge0,\ b<0$，真实差大于 $T_{max}$，回绕成负数）：真实情况是 $a>b$，而 $SF=1,\ OF=1$，所以 $SF\oplus OF=0$，判断为"不小于"，结果正确；
  3. 负溢出（$a<0,\ b>0$，真实差小于 $T_{min}$，回绕成正数）：真实情况是 $a<b$，而 $SF=0,\ OF=1$，所以 $SF\oplus OF=1$，判断为"小于"，结果正确。

也就是说，**溢出时符号位会"说谎"，用 `OF` 去纠正它**，就得到 $SF\oplus OF$。`jle`、`jg` 等再把 `ZF` 组合进去。

## 4. `if-else`：条件跳转

```c
long absdiff(long x, long y)
{
    long result;
    if (x > y) result = x - y;
    else       result = y - x;
    return result;
}
```

用 `gcc -Og -S -fno-if-conversion` 编译（关掉后面要讲的条件传送优化）：

```asm
absdiff:
    cmpq  %rsi, %rdi       # 计算 x - y，设置条件码
    jle   .L4              # x <= y 则跳到 .L4
    movq  %rdi, %rax
    subq  %rsi, %rax       # result = x - y
    ret
.L4:                       # x <= y
    movq  %rsi, %rax
    subq  %rdi, %rax       # result = y - x
    ret
```

寄存器用途：`%rdi` 是 `x`，`%rsi` 是 `y`，`%rax` 存返回值。

理解汇编的一个有效办法，是先把 C 改写成 **goto 风格**，它与汇编几乎一一对应：

```c
long absdiff_j(long x, long y)
{
    long result;
    int ntest = (x <= y);
    if (ntest) goto Else;
    result = x - y;
    goto Done;
Else:
    result = y - x;
Done:
    return result;
}
```

一般地，条件表达式 `val = Test ? Then_Expr : Else_Expr;` 的翻译模板是：

```c
    ntest = !Test;
    if (ntest) goto Else;
    val = Then_Expr;
    goto Done;
Else:
    val = Else_Expr;
Done:
    ...
```

编译器为 then 与 else 分别生成独立的代码块，根据测试结果只执行其中一个。

## 5. 条件传送指令 `cmov`

条件跳转有一个性能问题。**条件传送**则用另一种思路：**两个分支的值都算出来，再按条件选一个**。

```text
语义：if (Test) Dest ← Src
```

用 goto 风格表示：

```c
    result = Then_Expr;
    eval   = Else_Expr;
    nt = !Test;
    if (nt) result = eval;
    return result;
```

1995 年以后的 x86 处理器都支持这类指令，GCC 在确保"安全"的前提下会使用它们。同一个 `absdiff`，用 `-O1` 或 `-O2` 编译会得到：

```asm
absdiff:
    movq   %rdi, %rax
    subq   %rsi, %rax      # result = x - y
    movq   %rsi, %rdx
    subq   %rdi, %rdx      # eval   = y - x
    cmpq   %rsi, %rdi      # x : y
    cmovle %rdx, %rax      # 如果 x <= y，result = eval
    ret
```

`cmovle Src, Dest` 的读法与 `jle` 相同：前面 `cmpq %rsi, %rdi` 比较的是 `x` 与 `y`，条件成立（`x <= y`）就把 `Src` 复制给 `Dest`，不成立则什么也不做，没有任何跳转。代入两组数验证：

- `x=3, y=5`：`%rax = 3-5 = -2`，`%rdx = 5-3 = 2`，条件 `x <= y` 成立，`%rax ← %rdx = 2`，结果 2 ✓；
- `x=5, y=3`：`%rax = 2`，`%rdx = -2`，条件不成立，`%rax` 保持 2 ✓。

两种情形下执行的指令完全一样，只是 `cmovle` 有没有真的传送。

### 为什么要这样做：流水线

课件在这里补充了一段微体系结构背景。现代处理器采用**流水线**：把一条指令的执行拆成几个阶段，让多条指令像工厂流水线一样重叠执行。课件给的是经典的五级流水：取指（IF）、读寄存器（RD）、算术运算（ALU）、访存（MEM）、写回（WB）。

![](/obsidian-assets/d4bfff7bac647bc5.png)

**先用数字看一下流水线省了什么。** 假设一条指令要依次经过这五个阶段，每个阶段耗时一个时钟周期。如果一条指令做完才开始下一条，5 条指令要 $5\times5=25$ 个周期。而在流水线里，第 1 条指令进入"读寄存器"阶段时，第 2 条指令就已经可以去"取指"了，各阶段同时在处理不同的指令，像洗衣店里"洗、烘、叠"三台机器同时各干各的。于是第 1 条指令在第 5 周期完成，之后**每个周期完成一条**，5 条指令只需要 $5+4=9$ 个周期。指令越多越接近"每周期一条"。

**这个好处有一个前提：下一条指令必须能不间断地送进来。** 流水线要想跑满，需要持续不断地知道下一条指令是什么。顺序执行没有问题，遇到**条件跳转**时就麻烦了：跳不跳要看条件码，而条件码要等前面的 `cmp` 走到"算术运算"那一级才能产生，这时后面的指令已经在取指、读寄存器了，处理器却还不知道"下一条指令的地址是顺序的那条还是跳转目标"。为了不让流水线空等，处理器会先**猜**一个方向（这叫**分支预测**）继续取指。猜对了，什么都没损失；猜错了，已经进入流水线的那几条错误指令必须**全部作废**，再从正确的地址重新开始取指，白白浪费的周期数大致和流水线的深度相当（几级流水线就浪费大约几个周期）。流水线越深，猜错一次的代价越大。课件的数据是：现代通用处理器支持深度流水线与多发射，比如奔腾 4 有 20 多级流水线，同时最多有 126 条指令在运行，因此**条件跳转往往会带来性能损失，需要尽量消除**。`cmov` 没有跳转，只是一条普通的数据传送指令，下一条指令永远是紧邻的那一条，所以不存在猜错的问题。代价是**两个分支的值都要算**，所以它适合分支里计算量小、且条件很难预测的场合。

### 条件传送的限制

不是所有的条件表达式都能用 `cmov`，因为它要求**两个分支都先算出来**：

1. **Then 或 Else 表达式有副作用**：例如
   ```c
   int xgty = 0, xltey = 0;
   int absdiff_se(int x, int y)
   {
       int result;
       if (x > y) { xgty++; result = x - y; }
       else       { xltey++; result = y - x; }
       return result;
   }
   ```
   两个分支各自修改一个计数器，如果两个分支都先执行，计数就乱了；
2. **Then 或 Else 表达式的计算量较大**：两个分支都要算，浪费会超过省下的预测失败代价。

（另一类典型的不安全情况是分支里有指针解引用，比如 `p ? *p : 0`，提前计算 `*p` 可能访问非法地址。这是补充说明，课件里的描述是"在确保安全的前提下才使用"。）

### 练习一：条件传送

```c
int test(long x, long y) { return (x > y) ? x + y : x - y; }
```

```asm
test:
    movl  %esi, %eax
    [填空1] %eax
    cmpq  %rsi, %rdi
    cmovg [填空2], [填空3]
    addl  %edi, %eax
    ret
```

最后一条运算是 `addl %edi, %eax`，即 `eax += x`。要让它同时能算出 `x + y` 和 `x - y`，`%eax` 在加之前必须分别是 `y` 或 `-y`：

- 一开始 `movl %esi, %eax` 令 `eax = y`；
- 填空 1 应当把它变成 `-y`，即 **`negl`**（默认情形对应 `x <= y`，结果是 `x - y`）；
- 若 `x > y`，则要让 `eax` 变回 `y`，所以 `cmovg` 把 `y` 传回去：填空 2 是 **`%esi`**，填空 3 是 **`%eax`**。

代入检验：`x=5, y=3`（`x>y`）时，`%eax` 先是 3，再变成 −3，`cmovg` 把 3 传回，最后 `3+5=8` 即 `x+y` ✓；`x=2, y=3`（`x<=y`）时，`%eax = -3` 不动，`-3+2=-1` 即 `x-y` ✓。可见编译器的思路是：把"选哪一个运算"转化成"选加上的是 `y` 还是 `-y`"，全程没有跳转。

### 练习二：`likely` 与 `unlikely`

课件给了一个例子，代码里用 `__builtin_expect` 包装的宏告诉编译器某个分支"很可能"或"不太可能"发生：

```c
#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)
...
if (unlikely(a == 2)) { a++; b++; } else { a--; b--; }
```

在 `-O2` 下，写 `unlikely(a == 2)` 与写 `likely(a == 2)`，**程序的语义完全相同，生成的指令序列却不一样**。`a` 来自命令行参数（`atoi`），`b = a*a`，之后 `a == 2` 时算 `a+1` 与 `b+1`，否则算 `a-1` 与 `b-1`，最后返回 `a+b`。课件给出的两份汇编（省略共同的前半部分）：

```asm
# 写 unlikely(a == 2)：a==2 是"不太可能"的分支
    movl  %eax, %esi          # esi = a
    movl  $3, %ecx            # 预先令 a+1 = 3（因为这个分支里 a 必为 2）
    imull %eax, %esi          # esi = b = a*a
    cmpl  $2, %eax            # 比较 a : 2
    leal  1(%rsi), %edx       # edx = b+1（先算好；lea 不改条件码，所以插在 cmp 与 je 之间不影响）
    je    .L3                 # a == 2 才跳走
    leal  -1(%rax), %ecx      # 否则（顺序执行）：ecx = a-1
    leal  -1(%rsi), %edx      #                    edx = b-1
.L3:
    leal  (%rcx,%rdx), %eax   # 返回 a+b

# 写 likely(a == 2)：a==2 是"很可能"的分支
    movl  %eax, %ecx
    imull %eax, %ecx          # ecx = b
    cmpl  $2, %eax
    jne   .L2                 # a != 2 才跳走
    leal  1(%rcx), %eax       # 顺序执行：eax = b+1
    movl  $3, %edx            #           edx = a+1 = 3
.L3:
    addl  %edx, %eax          # 返回 a+b
    ret
.L2:                          # a != 2 的代码放在后面
    leal  -1(%rax), %edx
    leal  -1(%rcx), %eax
    jmp   .L3                 # 做完再跳回去
```

对比可以看出：**编译器把"可能发生"的那条路径排成顺序执行，把"不太可能"的那条路径放到跳转之后。**`unlikely(a==2)` 时，`a != 2` 是顺序往下走的；`likely(a==2)` 时，`a == 2` 紧跟在 `jne` 后面，而 `a != 2` 要跳到 `.L2`，执行完还要再 `jmp` 回来。

这样安排的理由仍然是流水线。顺序执行时，下一条指令就是紧邻的那条，取指不会被打断；而一旦发生跳转，处理器就得预测、改取指地址，预测错了还要作废已取的指令。把大概率走的路径排成**不跳转**的那条，大多数时候流水线就能畅通。（另外还能看到，当 `a == 2` 已知时，`a+1` 被直接算成常数 3，所以才有 `movl $3, ...`。）

## 6. 循环

循环在汇编里没有专门的指令，全部是"**条件跳转 + 回到前面**"。

### 6.1 do-while

```c
long pcount_do(unsigned long x)    // 统计 x 的二进制表示中 1 的个数
{
    long result = 0;
    do {
        result += x & 0x1;
        x >>= 1;
    } while (x);
    return result;
}
```

对应的 goto 风格与汇编：

```c
    long result = 0;
loop:
    result += x & 0x1;
    x >>= 1;
    if (x) goto loop;
    return result;
```

```asm
    movl  $0, %eax          # result = 0
.L2:                        # loop:
    movq  %rdi, %rdx
    andl  $1, %edx          # t = x & 0x1
    addq  %rdx, %rax        # result += t
    shrq  %rdi              # x >>= 1（x 是无符号数，所以是逻辑右移）
    jne   .L2               # if (x) goto loop
    ret
```

先弄清这段程序在做什么。`x & 0x1` 是"取出 `x` 的最低一位"（和 1 做按位与，只有最低位会保留），`x >>= 1` 是"把 `x` 右移一位，让下一位成为最低位"。每一轮取一位、加到 `result` 上、再右移，直到 `x` 变成 0，就把每一位上的 1 都数到了。以 `x = 0b1011`（十进制 11）为例：

| 轮次 | 本轮取出的最低位 | `result` | 右移后 `x` | `x == 0`？ |
|---|---|---|---|---|
| 1 | 1 | 1 | `0b101` | 否，继续 |
| 2 | 1 | 2 | `0b10` | 否，继续 |
| 3 | 0 | 2 | `0b1` | 否，继续 |
| 4 | 1 | 3 | `0b0` | 是，退出 |

结果 3，正好是 `1011` 里 1 的个数。再对着汇编看：`andl $1, %edx` 是取最低位；`shrq %rdi` 是只写一个操作数的移位指令，**含义是右移 1 位**；因为 `x` 是 `unsigned`，用的是逻辑右移（高位补 0）。`shrq` 同时按移位后的结果设置了 `ZF`，所以后面直接用 `jne`（"`ZF=0` 即结果不为 0 则跳转"）就能判断 `x` 是否变为 0，不用再多写一条比较。

通用模板：`do Body while (Test);` 翻译成

```c
loop:
    Body
    if (Test) goto loop;
```

### 6.2 while：两种翻译方式

`while (Test) Body` 比 do-while 多了一次"进入循环前先判断"。编译器有两种做法。

**方式一：跳到中间（jump-to-middle）**，`-Og` 使用：

```c
    goto test;
loop:
    Body
test:
    if (Test) goto loop;
done:
```

先无条件跳到循环尾部的判断处，由判断决定是进入循环体还是退出。

**方式二：转成 do-while（guarded-do）**，`-O1` 使用：

```c
    if (!Test) goto done;
loop:
    Body
    if (Test) goto loop;
done:
```

先判断一次，不满足就直接跳过，满足则按 do-while 执行。它多复制了一份 `Test`，但循环每轮少执行一条跳转指令，通常更快。

用统计 1 的个数的例子：

```c
long pcount_while(unsigned long x)
{
    long result = 0;
    while (x) {
        result += x & 0x1;
        x >>= 1;
    }
    return result;
}
```

| | jump-to-middle（`-Og`） | guarded-do（`-O1`） |
|---|---|---|
| 进入循环前 | `goto test;` 先跳到判断 | `if (!x) goto done;` 先判断 |
| 循环体之后 | `test: if (x) goto loop;` | `if (x) goto loop;` |

### 6.3 for

`for (Init; Test; Update) Body` 等价于：

```c
    Init;
    while (Test) {
        Body
        Update;
    }
```

然后再按 while 的方式翻译。例如逐位统计的版本：

```c
#define WSIZE 8*sizeof(int)
long pcount_for(unsigned long x)
{
    size_t i;
    long result = 0;
    for (i = 0; i < WSIZE; i++) {
        unsigned bit = (x >> i) & 0x1;
        result += bit;
    }
    return result;
}
```

其中 `Init` 是 `i = 0`，`Test` 是 `i < WSIZE`，`Update` 是 `i++`，`Body` 是花括号里的两句。按 jump-to-middle 的方式写成 goto 风格就是：

```c
    long result = 0;
    size_t i = 0;                       // Init
    goto test;
loop:
    unsigned bit = (x >> i) & 0x1;      // Body
    result += bit;
    i++;                                // Update
test:
    if (i < WSIZE) goto loop;           // Test
    return result;
```

注意 `Update` 放在 `Body` 之后、`Test` 之前，所以"先判断、再执行循环体、最后 `i++`"的顺序和 `for` 的语义完全一致。（课件示例里 `WSIZE` 是 `8*sizeof(int)`，即 32，而 `x` 是 64 位，因此只统计低 32 位；这对理解翻译方式没有影响。）

### 练习三：由汇编还原 C 代码

还原的步骤是：**先确定每个寄存器对应哪个变量，再逐条把汇编翻成赋值语句，最后看跳转回到哪里、条件是什么**。`test` 有两个参数：`val` 在 `%edi`，`input` 在 `%esi`（32 位 `int`，用 `%edi`、`%esi` 这样的 32 位寄存器名）。

```asm
test:
    testl  %edi, %edi
    js     .L6                  # val < 0，直接返回 0
    movl   $0, %edx             # i = 0
    movl   $0, %eax             # local = 0
.L5:
    leal   2(%rax), %ecx        # ecx = local + 2
    leal   (%rax,%rax), %r8d    # r8d = 2 * local
    cmpl   %eax, %esi           # input : local，计算 input - local
    movl   %ecx, %eax           # local = local + 2
    cmovle %r8d, %eax           # 若 input <= local，则 local = 2 * local
    addl   $2, %edx             # i += 2
    cmpl   %edx, %edi           # val : i，计算 val - i
    jge    .L5                  # val >= i 则继续循环
    ret
.L6:
    movl   $0, %eax
    ret
```

```c
int test(int val, int input)
{
    int local = 0;
    int i = 0;
    for (i = 0; i [填空1] val; i += [填空2]) {
        if (local < input)
            local += 2;
        else
            [填空3];
    }
    return local;
}
```

先把各条指令翻成人话，寄存器的对应关系是 `%edx = i`、`%eax = local`、`%ecx` 与 `%r8d` 是临时值：

| 指令 | 含义 |
|---|---|
| `testl %edi,%edi` + `js .L6` | `val` 自己与自己做 `&`，`js` 在为负时跳转：`val < 0` 就直接返回 0 |
| `leal 2(%rax),%ecx` | `ecx = local + 2`（`leal` 用来做加法，见第四讲；`2(%rax)` 就是 `%rax + 2`） |
| `leal (%rax,%rax),%r8d` | `r8d = local + local = 2*local` |
| `cmpl %eax,%esi` | 计算 `input - local`，比较 `input` 与 `local` |
| `movl %ecx,%eax` | 先令 `local = local + 2` |
| `cmovle %r8d,%eax` | 若 `input <= local`，改为 `local = 2*local` |
| `addl $2,%edx` | `i += 2` |
| `cmpl %edx,%edi` + `jge .L5` | 比较 `val` 与 `i`，`val >= i` 就回到循环开头 |

可以用 `val=4, input=3` 代入：第 1 轮 `local=0`，`input<=local`（3<=0）不成立，所以 `local=2`，`i=2`；第 2 轮 `local=2`，3<=2 不成立，`local=4`，`i=4`；第 3 轮 `local=4`，3<=4 成立，`local=8`，`i=6`，`val>=i`（4>=6）不成立，退出，返回 8。与 C 版本对照：`i` 取 0、2、4 三轮，`local` 先 `<input` 加 2 两次，之后不再小于 `input` 而翻倍，也得到 8 ✓。

- 填空 1：循环继续的条件是 `val >= i`，也就是 `i <= val`，填 **`<=`**。开头的 `testl / js` 对应 `val < 0` 时一次循环都不进入，与 `i = 0 <= val` 不成立相符；
- 填空 2：`addl $2, %edx` 说明步长是 **2**；
- 填空 3：`cmovle` 在 `input <= local` 时把 `local` 改为 `2 * local`，所以 else 分支是 **`local *= 2`**。

这道题里，if-else 被编译器用 `cmov` 实现了（两个分支的值都先算好），循环本身是 guarded-do 的形式。

## 7. `switch` 语句

`switch` 有两种实现方式，编译器依据情况选择：

- 用一组 `if-then-else`（分支少、取值稀疏时）；
- 用**跳转表（jump table）**（分支多、取值密集时）。可以用编译选项 `--param case-values-threshold=1` 强制编译器多用跳转表。

先想一想为什么需要跳转表。如果 `switch` 有 100 个 case，用 `if-else` 就是最坏要连续比较 100 次，才找到该跳的位置。可是 case 的值恰好是 0、1、2、…这样的小整数，**值本身就可以当作下标**：事先把每个 case 对应的代码块的**地址**，按 case 的值依次排成一个数组 `JTab`，运行时用 `x` 去取 `JTab[x]`，得到目标地址再跳过去，相当于 C 里写 `goto *JTab[x];`。这样不管有多少个 case，都只需要**一次**取地址和**一次**间接跳转，与 case 的个数无关，这就是"表"的意义。

### 例子

```c
long switch_eg(long x, long y, long z)
{
    long w = 1;
    switch (x) {
    case 1:
        w = y * z;
        break;
    case 2:
        w = y / z;
        /* Fall through */
    case 3:
        w += z;
        break;
    case 5:
    case 6:
        w -= z;
        break;
    default:
        w = 2;
    }
    return w;
}
```

这个例子包含了 switch 里的几种典型情况：**多个 case 共用一段代码**（`case 5` 与 `case 6`）、**落空（fall through）**（`case 2` 执行完直接进入 `case 3`）、**缺失的 case**（没有 `case 0` 和 `case 4`，都走 default）。

编译后的入口：

```asm
switch_eg:
    movq  %rdx, %rcx          # 把 z 挪到 %rcx（%rdx 要留给除法用）
    cmpq  $6, %rdi            # x : 6
    ja    .L8                 # x > 6（无符号比较）则跳到 default
    jmp   *.L4(,%rdi,8)       # goto *JTab[x]
```

这里有一个值得想一想的地方，课件问的是 `why?`：**为什么先比较 `x : 6`，而且用的是 `ja`（无符号）？** 因为表里只有下标 0 到 6 这 7 项，`x` 不在这个范围内时不能去查，否则会把表后面不相干的内存当成地址去跳转。本来要排除两种情况（`x < 0` 和 `x > 6`），要两次比较。用**无符号**比较一次就够了：`x > 6` 当然被排除；`x = -1` 时，64 位补码是 `0xFFFFFFFFFFFFFFFF`，按无符号看是 $2^{64}-1$，同样大于 6，所以也会跳到 default。这又用上了第二讲讲的"负数在无符号看来是大数"。

跳转表本身放在只读数据段 `.rodata` 里，每项 8 字节，存的是目标地址：

```asm
    .section .rodata
    .align 8
.L4:
    .quad .L8      # x = 0
    .quad .L3      # x = 1
    .quad .L5      # x = 2
    .quad .L9      # x = 3
    .quad .L8      # x = 4
    .quad .L7      # x = 5
    .quad .L7      # x = 6
```

![](/obsidian-assets/bba2c5fc4957f5a8.png)

先把这条指令逐段读清楚，它是本篇最难读的一条：`jmp *.L4(,%rdi,8)`。

- 括号里是第四讲讲的 $D(R_b,R_i,S)$：常数 $D=$ `.L4`（跳转表在内存里的**起始地址**，汇编器记成标号），没有基址（逗号前留空），变址寄存器是 `%rdi`（即 `x`），比例因子 $S=8$。所以有效地址是 $.L4+8x$，也就是**表的第 $x$ 项所在的位置**，每项占 8 字节，因此要乘 8；
- 前面的 `*` 表示**间接**：先**去这个地址读出 8 字节**，读出来的值才是要跳转的目标地址，而不是直接跳到这个地址；
- 汇编伪指令方面：`.section .rodata` 说明接下来的内容放在只读数据段；`.align 8` 要求表的起始地址是 8 的倍数；`.quad .L8` 的意思是放一个 8 字节整数，其值为标号 `.L8` 对应的地址。

举例：`x=2` 时，地址是 `.L4 + 16`，是表里的第三项（下标 2），里面存着 `.L5`，于是跳到 `.L5` 执行 case 2 的代码；`x=0` 与 `x=4` 的表项都是 `.L8`，对应没有写出的 case，它们都跳到 `default`。

注意两种跳转写法的区别：

- **直接跳转** `jmp .L8`：跳到标号 `.L8` 所表示的地址，目标是固定的；
- **间接跳转** `jmp *.L4(,%rdi,8)`：先用地址表达式 `.L4 + 8*%rdi` 算出**存放目标地址的那个内存单元**，从里面取出目标地址，再跳转过去。这里正好用上上一篇的变址寻址 $D(R_b,R_i,S)$，比例因子 8 对应每项 8 字节。

各个 case 对应的代码：

```asm
.L3:                         # case 1：w = y*z
    movq  %rsi, %rax         # y
    imulq %rdx, %rax         # y*z
    ret
.L5:                         # case 2：w = y/z，然后落入 case 3
    movq  %rsi, %rax
    cqto                     # 把 %rax 符号扩展到 %rdx:%rax
    idivq %rcx               # y / z
    jmp   .L6                # goto merge
.L9:                         # case 3：w = 1
    movl  $1, %eax
.L6:                         # merge:
    addq  %rcx, %rax         # w += z
    ret
```

```asm
.L7:                         # case 5, case 6：w -= z
    movl  $1, %eax           # w = 1（初始值）
    subq  %rdx, %rax         # w -= z
    ret
.L8:                         # default：w = 2
    movl  $2, %eax
    ret
```

**fall through 的处理方式**是：让 `case 3` 的代码块里 `w += z` 这一句成为一个公共出口 `merge`，`case 2` 做完自己的事就 `goto merge`，`case 3` 则先令 `w = 1` 再顺序进入 `merge`。其中 `cqto` 与 `idivq` 是除法所需，这里需要单独说明：`idivq S` 是 64 位有符号除法，规定**被除数是 128 位，由 `%rdx`（高 64 位）和 `%rax`（低 64 位）拼成**，除数是 `S`，商放进 `%rax`，余数放进 `%rdx`。而 C 里 `y / z` 的被除数 `y` 只有 64 位，所以要先用 `cqto` 把 `%rax` 的符号位扩展到 `%rdx`（`y` 为负数时 `%rdx` 全是 1，否则全是 0），拼成一个等值的 128 位数，才能交给 `idivq`。这也解释了入口处为什么把 `z` 先挪到 `%rcx`：`%rdx` 本来装着参数 `z`，要被 `cqto` 覆盖，除数必须放在别处。

### 跳转表的适用范围

跳转表要求 case 的取值比较**密集**。如果 case 稀疏（例如 1、1000、100000），表会巨大而且大多数项是浪费的，这时编译器会改用**平衡二叉树**的方式组织比较，把查找次数降到 $O(\log n)$：

![](/obsidian-assets/e0eaf139de126c1a.png)

图中每个节点先与某个 case 值比较：相等则取对应分支；小于走左边，大于走右边，没有匹配就落到默认分支。

## 8. 跳转指令的目的地址怎么"定位"

第四讲提到了几类"定位"问题，这一讲补上跳转的这一类。看一段反汇编：

```text
 53: 89 45 ec          mov    %eax,-0x14(%rbp)     # val
 56: 83 7d ec 00       cmpl   $0x0,-0x14(%rbp)     # val >= 0 ?
 5a: 78 05             js     61                   # no
 5c: 8b 45 ec          mov    -0x14(%rbp),%eax     # yes: %eax = val
 5f: eb 05             jmp    66
 61: b8 ff ff ff ff    mov    $0xffffffff,%eax     # %eax = -1
 66: 48 83 c4 18       add    $0x18,%rsp
```

机器码里 `78` 是 `js`，`eb` 是无条件 `jmp`，后面的 `05` 就是跳转的目标信息：它是一个**相对偏移量**，目标地址 = **下一条指令的地址** + 偏移量。验证：`js` 位于 `0x5a`，占 2 字节，下一条指令在 `0x5c`，加 5 得 `0x61` ✓；`jmp` 位于 `0x5f`，下一条在 `0x61`，加 5 得 `0x66` ✓。

为什么要存成"相对偏移"而不是目标的绝对地址？因为这样机器码里不含任何绝对地址，整段代码被装到内存的哪里，偏移都不用改。偏移是有符号数，**向前跳（回到循环开头）时是负数**。例如编译前面的 `pcount_do`，循环末尾是 `14: 75 ef  jne 5`：`75` 是 `jne`，`ef` 按补码是 −17，下一条指令在 `0x16`，$0x16+(-17)=0x5$，正好回到循环开头 ✓。

**直接跳转**的目标在编译、汇编时就可以确定；而**间接跳转**（如跳转表那一条）的目标地址是存在表里的**绝对地址**，在编译时还不知道各代码块最终会被放在哪里，需要在**链接阶段**由链接器填写，这是第九讲重定位要讲的内容。

## 9. 补充：写寄存器的副作用

x86-64 里，同一个寄存器可以用不同的宽度访问（`%rax`、`%eax`、`%ax`、`%al`）。写它们的时候，**其余的位会怎样**，规则并不一样：

- **写 32 位（`%eax`）会把高 32 位清零**：例如 `movl $-1, %eax` 之后，`%rax = 0x00000000FFFFFFFF`，而不是全 1。第 3 节里 `movzbl %al, %eax` 能得到干净的结果，靠的就是这一点；
- **写 8 位、16 位（`%al`、`%ax`）则保留其余位不变**：`movb $-1, %al` 只改最低一个字节。

为什么这个区别重要？处理器内部是流水线（第 5 节），后面的指令往往要**读整个寄存器**。如果前面只改了其中的一部分，后面读取时硬件必须把"新写入的那部分"和"旧值里没被改的部分"**合并**起来，这就产生了额外的数据依赖（课件称为 partial data dependence），可能引入额外的微操作和流水线停顿。x86-64 把 32 位写入规定为"整体更新、高位清零"，这样 `%eax` 的写入就不依赖旧值，也就消除了这种依赖。

## 小结

1. 控制流靠**条件码 + 条件跳转**实现。条件码 `CF/ZF/SF/OF` 由算术指令隐含设置，`cmp` 和 `test` 只设置条件码，不保存结果。
2. `setX` 把条件读成一个 0/1 字节，`jX` 据此跳转。**有符号比较读 `SF^OF` 与 `ZF`，无符号比较读 `CF` 与 `ZF`**；硬件不区分类型，类型的语义靠编译器**选择不同的指令**来体现。
3. 条件跳转会干扰流水线，所以在安全且划算的时候，编译器会改用 **`cmov`**：两个分支都算，再按条件选一个。有副作用或计算量大的表达式不能这样做。
4. 循环全部是"条件跳转 + 回跳"：do-while 最直接；while 有 jump-to-middle 与 guarded-do 两种翻译；for 先转成 while。
5. `switch` 在 case 取值密集时用**跳转表**，一次间接跳转 `jmp *JTab(,%rdi,8)` 完成分派，先用无符号比较排除越界；稀疏时用平衡二叉树。
6. 跳转的目的地址在机器码里是**相对偏移**，间接跳转的目标则需要链接阶段处理。
